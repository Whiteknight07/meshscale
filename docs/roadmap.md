# Roadmap

This is a public design proposal for a solo developer connecting Linux servers and a Mac, followed by small-team use. It describes release criteria rather than promised dates. The [feature inventory](tailscale-parity.md) distinguishes implemented subsets from missing capabilities.

The bundled OAuth client is public, so any Cloudflare account can sign in. The remaining release gates are sign-in trials with independent accounts, safe artifact distribution, and independent supported-host qualification; the [privacy/history review](release/history-audit.md) is complete and the repository was published with a fresh history. Release archives, the installer and attestations are published on GitHub Releases; supported-host qualification is still pending.

## Onboarding baseline and measurement method

Measure time from opening installation instructions to reaching a known named-peer TCP service. Record preparation, account activation, package/tool downloads, authentication, OS permissions, connection, DNS, operator assistance, and failures separately. Compare prepared-account and fresh-account cohorts; include competing-VPN migration as a separate case. Do not present documentation-derived estimates as timed user trials.

Proposed targets are a prepared Linux account reaching a peer in at most four user-visible phases and a median five minutes, and a Mac in five phases and seven minutes. These are budgets to validate, not observed results. Recruit at least five independent users per platform, report all durations and completion/assistance fractions, and do not infer a stable p95 from five trials. Store timings/error categories rather than raw account diagnostics.

## Ranked next 15 items

Effort is focused engineering time for one person, including validation, with working vendor APIs and available test hardware; external approvals/waits are additional. **S = 1–3 days, M = 4–7 days, L = 2–3 weeks**. Risk describes security, vendor/platform uncertainty and delivery exposure. Dependencies affect execution order even when user value ranks an item higher. Every acceptance criterion below is future work, not a result of this audit.

Sequence: unblock distribution (#1), deliver install artifacts (#2–3), qualify safe lifecycle/performance (#4–5), then daily usability (#6–8). Headless enrollment (#9) needs revocation semantics from #11 even though onboarding value ranks higher. Team tags (#12) extend the existing control contract. Subnet, container and hostname delivery can share vendor profile/route primitives; keep one authoritative owner for each resource.

## Explicitly deferred gaps and feasibility gates

- **Windows** is a meaningful competitor gap (C3), next after this Linux/Mac queue unless product priority changes. Use official One client plus service/named-pipe UI; require a Windows test machine and signing/distribution plan, not a new driver. Phone enrollment deserves attended iOS/Android verification; no new meshscale mobile VPN. Intel Mac, NAS native packages, tvOS, ChromeOS and Fire are uncommitted platform expansions, not inferred support.
- **Router HA** can follow #10/#13 via vendor active-passive CIDR replicas. Requires HA at node creation, same subnet/routing and at least two hosts; outbound site routing is not vendor client failover. Do not promise stable replica Mesh IPs or hostname HA.
- **Cross-platform full exit selection** remains a major parity gap. Investigate supported vendor public-CIDR/client-profile routing in a disposable account before any new endpoint stack; `0/0`, `::/0`, per-client independence and DNS behavior remain unproven. Linux secure exits already exist; physical reboot/namespace recreation and large-UDP qualification remain release gates, not another exit implementation item.
- **SSH check mode/recording** is an acceptance gate for Cloudflare SSH. Session-duration controls are documented; exact Tailscale check-period or mandatory-recorder behavior is not established. Cloudflare terminates SSH and can inspect plaintext. Downloaded command logs are best effort; Enterprise Logpush is a separate guarantee/cost and not equivalent to fail-closed admission when a recorder is unavailable.
- **Serve HTTPS**, after the existing cert work, may wrap a proven reverse proxy/library; do not implement a general file server, arbitrary application-capability protocol or floating private VIP fabric. **Guest app sharing** should reuse Access/Tunnel publication; it is not cross-account device federation.
- **`tailscale web`** equivalent can reuse the existing console design with a loopback adapter later. CSRF/origin/auth requirements apply before exposing daemon controls. Stable metrics output, completion/wait helpers, multi-account switching, endpoint collection and signed/retried webhooks are useful follow-ups after core workflow completion; no second polling loop or telemetry service.
- **Taildrop is explicitly excluded** in [plan.md](plan.md); document stock SCP/SFTP. Taildrive, embedded transport SDK, tsidp/OIDC issuer, PAM vault/protocol suite and Aperture AI suite do not justify new security/data infrastructure. **Tailnet Lock** has no equivalent established in Mesh: independent signing/recovery would add a security system owned by meshscale and is deferred. Device approval is not its substitute.

## Design assumptions

| Decision | Consequence |
| --- | --- |
| **Domain: reuse an authorized account zone where appropriate.** | Existing zone for OAuth website/verification, console, stable Funnel and device-certificate names. Choose an appropriate subdomain during those existing tasks; buying another domain is not a blocker. `.mesh` cannot receive public CA certificates. |
| **Ad-hoc Mac distribution during development.** | Ship a labeled ad-hoc developer Mac bundle with manual Open instructions; notarization/App Store distribution and a new signed network extension are deferred. The official Cloudflare client supplies the VPN. |
| **No direct links.** | Cloudflare carries all traffic. No custom NAT traversal, DERP, peer relays or carrier replacement. Same-LAN direct-link speed is not a release promise. |
| **Thin Cloudflare layer with explicit trust boundaries.** | Official client default, Gateway/Access enforce policy, stock OpenSSH where possible; existing optional Linux encryption remains over Mesh. Worker stores control metadata and never forwards user traffic. |
| **Workers + Effect + Alchemy; no Taildrop.** | Extend the current components and their contracts rather than duplicating them. |

Maintainer decisions before broad distribution:

1. **Public release gate (done 2026-10-27):** the OAuth client is public, verified on `meshscale.stavan.ai`.
2. **Support promise:** keep the proposed first cohort Debian/Ubuntu amd64/arm64 and Apple Silicon macOS 14+, or fund Windows/Intel/NAS coverage sooner. The ranking assumes the former; source portability is not a support commitment.
3. **Plan/cost ceiling:** treat Free-plan core behavior as the default; decide whether Enterprise-only resolver/logging features merit optional tiers. Present actual entitlement/cost before enabling paid resources.
4. **Trust/migration defaults:** decide when proven Cloudflare SSH can become the recommended default, with its plaintext-at-edge tradeoff; whether users needing universal peer E2EE or mobile/home exits are outside the initial audience. Do not hide those gaps in a parity score.
5. **Team identity scope:** choose initial supported IdP/invite population and guest app-sharing expectations before #12; avoid assuming team members are Cloudflare account administrators.

## Research evidence and boundaries

Read README, plan and all top-level documentation, including historical secure/exit/SSH evidence; checked the installed **Tailscale 1.98.8** CLI via **119 help-only invocations**, plus version. Current primary sources correct older repo assumptions: [Mesh routes](https://developers.cloudflare.com/mesh/features/routes/) include public hostname egress; [HA](https://developers.cloudflare.com/mesh/features/high-availability/) and the [official container](https://developers.cloudflare.com/mesh/guides/run-mesh-in-containers/) exist; [Access Infrastructure](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/non-http/infrastructure-apps/) explicitly permits Mesh; [Resolver Policies](https://developers.cloudflare.com/cloudflare-one/traffic-controls/resolver-policies/) require Enterprise. See the parity document for feature-by-feature citations and blockers.

All numerical onboarding budgets are proposed targets; performance numbers attributed to existing docs are historical observations. No fresh onboarding or network experiment is implied by this roadmap.
