# Tailscale parity and Cloudflare mapping

Research snapshot: **2026-10-26**. This comparison describes a development snapshot, not a released guarantee. Proposed mappings require separate vendor, plan, and platform validation. The ranked plan is in [roadmap.md](roadmap.md).

## Scope and evidence rules

The reference CLI on this Linux host is **Tailscale 1.98.8**, commit `1241b225bc798707d02db3570992625d3a16594f`, Go `go1.26.3`. Ran `tailscale --help`, recursively every advertised subcommand's `--help`, and hidden `tailscale debug --help` plus its subcommands: **119 help invocations including root**, all exit 0. Only help/version were executed; no login, routing, host diagnostics, or device changes. The complete command inventory appears below, including features beyond the initial brief (Taildrive, Services, workload identity, local web UI, policy diagnostics).

The installed CLI is a versioned Linux sample, not the complete current cross-platform product. The audit covers network/client/admin feature families and separately accounts for adjacent PAM/Aperture products; it does not claim every vendor integration or every UI control has a one-to-one replacement. Current vendor documentation/KB supplies the additional platform and administrative features. Links in each row are primary sources; current docs may describe newer versions than 1.98.8. Product/API mappings are **proposals/inferences**, unless repo evidence explicitly records implementation/live verification. A Cloudflare API being present does not prove OAuth permission, plan eligibility, propagation, or successful end-to-end behavior.

- **Done**: the scoped baseline behavior exists with implementation/evidence; this does not mean complete Tailscale compatibility or production certification.
- **Partial**: a useful subset exists, a platform is unsupported, or release/live evidence is missing.
- **Missing**: no supported meshscale workflow; a deliberate exclusion is still a parity gap.
- **Fit yes**: small orchestration/UI/policy translation over a supported Cloudflare product. **Conditional**: requires a feasibility/plan gate or endpoint work. **No**: would require a new transport, crypto trust system, or substantial file/service infrastructure.

**Architecture gate:** [plan.md](plan.md) is binding. Cloudflare carries traffic. No direct links, DERP replacement, NAT traversal, custom carrier, or new packet relay. The already implemented Linux WireGuard-over-Mesh/exit features remain bounded exceptions to a strictly minimal wrapper; they do not justify expanding into a second cross-platform VPN stack. Prefer Cloudflare Access, Gateway, official clients, and stock OpenSSH for security work. Ordinary Mesh trusts Cloudflare; Linux `.secure` is optional end-to-end encryption with an account/API trust root, not Tailnet Lock.

## Primary Cloudflare references and material differences

These sources establish vendor capabilities, not implemented meshscale parity. Product proposals above still need the acceptance gates in [roadmap.md](roadmap.md).

- [Mesh overview](https://developers.cloudflare.com/mesh/), [concepts](https://developers.cloudflare.com/mesh/concepts/), [CIDR/hostname routes](https://developers.cloudflare.com/mesh/features/routes/), [HA](https://developers.cloudflare.com/mesh/features/high-availability/) and [official Docker/Kubernetes image](https://developers.cloudflare.com/mesh/guides/run-mesh-in-containers/): the official image/hostname routes/HA are available now, although older repo research lists some as future work. MASQUE is required for hostname routes, IPv6 CIDRs and HA.
- [Cloudflare OAuth launch/visibility](https://developers.cloudflare.com/changelog/post/2026-06-03-public-oauth-clients/) and [repo OAuth/API findings](setup.md): domain verification/public-client distribution is a product-owner release gate, not an extra secret to embed in binaries.
- [Official client downloads](https://developers.cloudflare.com/cloudflare-one/team-and-resources/devices/cloudflare-one-client/download/), [device enrollment](https://developers.cloudflare.com/cloudflare-one/team-and-resources/devices/cloudflare-one-client/deployment/device-enrollment/), [device posture timing](https://developers.cloudflare.com/learning-paths/secure-internet-traffic/configure-device-agent/device-enrollment-permissions/) and [device revocation](https://developers.cloudflare.com/cloudflare-one/team-and-resources/devices/device-registration/#revoke-a-device-registration): vendor mobile/Windows support is not a tested meshscale client; registration revocation and removal of re-enrollment rights are distinct operations.
- [DNS policies/overrides](https://developers.cloudflare.com/cloudflare-one/traffic-controls/dns-policies/), [Local Domain Fallback](https://developers.cloudflare.com/cloudflare-one/team-and-resources/devices/cloudflare-one-client/configure/route-traffic/local-domains/) and [Resolver Policies](https://developers.cloudflare.com/cloudflare-one/traffic-controls/resolver-policies/): plan-aware split DNS must distinguish local resolution from cloud-side resolution. Enterprise-only resolver features cannot be a Free-plan prerequisite.
- [Access for Infrastructure over Mesh](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/non-http/infrastructure-apps/), [SSH deployment](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/use-cases/ssh/ssh-infrastructure-access/), [2026-10-14 session-duration change](https://developers.cloudflare.com/changelog/post/2026-10-14-infrastructure-ssh-session-duration/) and [SSH log payloads](https://developers.cloudflare.com/cloudflare-one/insights/logs/dashboard-logs/ssh-command-logs/): vendor session limits/logging are real, but exact Tailscale check/recorder guarantees require comparison tests. Cloudflare terminates these SSH sessions; log-at-rest encryption does not make the proxy blind to plaintext.
- [Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) and [email-protected Quick Tunnels](https://developers.cloudflare.com/changelog/post/2026-10-02-protected-quick-tunnels/): temporary demos/guest app access can be domainless; stable production Funnel remains a separate domain/Tunnel lifecycle. Check installed `cloudflared` capability before offering email protection.
- [Origin CA trust limitation](https://developers.cloudflare.com/ssl/origin-configuration/origin-ca/troubleshooting/): use a publicly trusted CA for direct browser→Mesh TLS, not Origin CA.
- [Access logs](https://developers.cloudflare.com/cloudflare-one/insights/logs/dashboard-logs/access-authentication-logs/) and [API/Terraform](https://developers.cloudflare.com/cloudflare-one/api-terraform/): reuse vendor telemetry and infrastructure resources; validate dataset retention/Logpush/notification coverage for the user's plan.

No account settings, host routes, running services, credentials, or device enrollments were changed during this audit. Only this document and [roadmap.md](roadmap.md) are owned by the research task.
